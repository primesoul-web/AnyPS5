# libSceHmd2 technical debt

### Silent stubs

- [libSceHmd2](../../../core/libs/prx/libSceHmd2/Export.cpp) has no PS VR2 runtime: `sceHmd2Initialize` fails and `sceHmd2GetDeviceInformation` and `sceHmd2GetFieldOfViewWithoutHandle` answer `NOT_INITIALIZED` (0x8A720002), the constants [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/libHmd2.cpp) declares for the state each checks first, and every export it has that the reprojection session does not cover (and every [libSceVrTracker2](../../../core/libs/prx/libSceVrTracker2/Export.cpp) export) throws. PPSA01317 skips its whole VR set-up when initialization fails
- the reprojection session follows [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/libHmd2.cpp)'s state machine with the layouts its static_asserts pin: `sceHmd2ReprojectionQueryBufferSizeAlign` answers `sizeof/alignof` of the 16-byte, 8-aligned state (output mode, timing in microseconds), `sceHmd2ReprojectionInitialize` answers `PARAMETER_NULL` (0x8A720008) for a null param or buffer, throws for a see-through buffer (the host has no camera), writes the state into the guest's work buffer with the timing the param carries or the 3000 us default and answers 0, and a second initialization answers `REPROJECTION_ALREADY_INITIALIZED` (0x8A72000C). There is no reprojection stage on the host, so the session is bookkeeping only. `sceHmd2ReprojectionSetTiming` answers reprojection `NOT_INITIALIZED` (0x8A72000B) without a session, throws below 2000 us and above 7000 us (KytyPS5 aborts there, which is not portable) and otherwise records the value rounded up to the next hundred microseconds in the work buffer. `sceHmd2ReprojectionEnableVrMode` answers reprojection `NOT_INITIALIZED` without a session, `VIDEO_OUT_ERROR_INVALID_VALUE` (0x80290001) for an output mode other than KytyPS5's 89/91 Hz (0x2000C) and 119/88 Hz (0x2000F), and otherwise `VIDEO_OUT_ERROR_NO_DEVICE` (0x80290018, [KytyPS5 errno.h](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/errno.h)): the console reports no VR runtime, so the state's output mode stays 0

PPSA01317 passes a pointer to 16 zeroed bytes and only tests the result for non-zero
- the four error-reporting signatures follow [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/libHmd2.cpp), whose layouts are static_assert-checked: `sceHmd2GetDeviceInformation(SceHmd2DeviceInformation*)` with the 28-byte device information, `sceHmd2GetFieldOfViewWithoutHandle(SceHmd2FieldOfView*)` with the 16-byte tangents, `sceHmd2ReprojectionEnableVrMode(output_mode)` and `sceHmd2ReprojectionSetTiming(timing)`, and the 72-byte `sceHmd2ReprojectionInitialize(SceHmd2ReprojectionInitializeParam*)` follows the same file's layout. What the device and field-of-view calls return once initialization succeeded is not implemented: KytyPS5 fills a virtual headset's values there, which is its own invention, and the console values without a headset are unknown
